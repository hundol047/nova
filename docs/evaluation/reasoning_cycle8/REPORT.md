# 외부 고난도 추론 개선 — cycle 8

2026-10-03. 이 작업은 소프트웨어 개선과 평가 준비다. 실제 모델 학습이나 외부 임상
정확도 향상을 입증한 작업이 아니다. 공식 고정 모델 서버가 연결되지 않아 실모델 비교는
차단되었으며, 참가자용 공식 API에 맞춘 어댑터 검증도 남아 있다.

모델의 원인 추론이 실제로 좋아졌는지는 아직 측정하지 못했다. 카탈로그를 넓게 제공하면
토큰·지연 비용이 늘 수 있다. 인용문 검사는 관찰의 존재만 확인하며, 그 관찰이 특정 질환을
의학적으로 지지한다는 증명이 아니다. 엄격한 인용 검사로 올바른 바꿔쓰기도 탈락할 수 있다.
약물 상태 구조화의 기존 한계도 남아 있어 원문과 시점을 함께 제공한다.

## 실제 평가 결과

최종 재검증 결과는 `stable_*` 산출물과 `stable_comparison.json`을 기준으로 한다.
초기 `original/`, `external_nine/`, `comparison.json`은 마지막 강제 종료 보완 전 기록이다.
`guarded_*`, `final_*` 성능 실행은 테스트 임시 파일과 코드 해시 충돌이 있어 최종 성능
근거에서 제외했다. `evaluation_isolation_incident.json`에 원인과 재실행 이유를 기록했다.

| 평가 | 이전 | 이번 | 해석 |
|---|---:|---:|---|
| 고정 합성 400개, 최종 정답 일치 | 385/400, 96.25% | 385/400, 96.25% | 개발에 노출된 합성 변형·mock |
| 위 평가의 쉬운 사례 | 200/200 | 200/200 | 외부 일반화 보장 없음 |
| 위 평가의 어려운 사례 | 185/200, 92.5% | 185/200, 92.5% | 독립 임상 평가 아님 |
| 외부 표적 9개 전체 진단명 일치 | 0/9 | 0/9 | 공개 연구 증례, mock, 정답 검토에 이미 노출 |
| 실제 고정 모델 3방식 비교 | 미측정 | BLOCKED | 성공한 실제 모델 호출 0 |

소프트웨어 회귀의 초기 결과는 697 passed, 1 skipped였다. 마지막 안전 보완 후 결과는
**699 passed, 1 skipped**이며 `final_regression.txt`에 기록했다. 기존 `tests/test_production_api.py`는 관찰된 TestClient
정지 문제로 제외했다. 신경망 관련 테스트 1개가 건너뛰어졌으며 전체 서비스 통과를 주장하지 않는다.
합성 재평가에서 위험 신호 누락·과잉 경고도 추적한다. 이것은 위험 질환의 실제 임상 민감도가 아니다.

400개 모두 입력 해시·최종 답변·최종 위험 신호가 이전과 같다. 합성 위험 라벨 194개 중
최종 경고가 있었던 사례는 179개, 누락 15개다. 비위험 라벨 206개 중 경고 64개도 유지됐다.
고난도 위험 라벨의 최종 경고 비율은 90/105(85.71%)이며, 이것을 진단명 정답률과 혼동하지 않는다.
개발 사례 `SIM50_high_development_19057`의 턴 수는 9→24로 늘었다. 전체 턴 8,126→8,141이며
질문 효율 향상을 주장할 수 없다. 정답·위험 신호는 같지만 이 행동 경로 차이는 후속 조사 대상이다.

최종 런타임 SHA-256은 `83e6441bdc22c1042c83052a5572144618729abfb2524635b79ba661c28eb203`이다.
400개 평가·외부 9개 평가·실모델 차단 기록의 런타임 해시가 모두 일치한다. 제출 패키징과
독립 실행 smoke도 통과했다(`build.txt`). ZIP은 260,279바이트이며 외부 연구 자료·정답·테스트를
포함하지 않는다. 패키징 성공은 공식 제출 준비 완료를 뜻하지 않는다.

## 외부 평가의 분리와 채점

- 공개 DiagnosisArena에서 개발 59개, 검증 50개, 최종 평가 보관 100개를 준비했다. 모델 가중치를 학습시키지 않았다.
- 연구·모델 평가 전용 이용 조건을 유지하고 서비스 RAG·학습·제출물에 넣지 않았다.
- 원저자의 전문의 검토와 NOVA의 임상의 정답 승인·응급도 검증은 별개다. 후자는 미완료다.
- 모든 예측을 저장한 다음 정답 파일을 읽는다. 모델의 답을 보고 정답 동의어나 구성요소 점수를 자동 추가하지 않는다.
- Top-1은 최종 답변의 전체 진단명 일치, Top-3/5는 별도 후보 목록의 전체 진단명 일치다. 최종 답과 후보 목록이 다르면 Top-3가 Top-1보다 낮을 수 있다.
- 호출 실패와 fallback은 실제 모델 성공으로 계산하지 않는다. 실패한 시도는 전체 시도 기준 점수에서 오답으로 남는다. 자료 부족으로 차단된 대화형 평가는 null이다.
- 정적 증례에 없는 문진별 답변을 만들지 않는다. 검토된 행동→관찰 매핑을 확보하기 전 대화형 비교는 실행되지 않는다.
- 응급도 정답이 없어 외부 위험질환 민감도·특이도를 보고하지 않는다. calibration도 미완료다.
- 분할 간 어휘 중복은 검사하지만 환자/논문 family 및 의미 중복은 미검토다. 공개 자료가 모델 사전학습에 들어갔는지도 모른다.

## 다음 실행에 필요한 것

1. 주최 측이 허용한 개발 모델 endpoint와 인증 정보를 실행 환경에 설정한다. 토큰은 채팅·코드·커밋에 넣지 않는다.
2. 참가자용 공식 API 안내서로 `competition/schema.py`, `adapter.py` 및 합법 행동 목록을 대조한다. 현재 프로젝트 목록은 공식 API 검증 전이다.
3. 제공 서버가 규정의 고정 모델/revision인지 확인한다. 환경 변수의 모델 이름만으로 서버 가중치를 확인했다고 하지 않는다.
4. 개발 3개로 연결·출력 형식·비용·fallback을 먼저 확인하고, 개발 59개에서 실패를 분석한다. 검증 50개 확인 후 코드를 동결해 보관 100개를 평가한다.
5. 대화형 성능과 안전 지표에는 임상의가 검토한 관찰 매핑·위험도 정답이 필요하다. 승인 전에는 해당 결과를 발표하지 않는다.

실행 예시는 [RUNBOOK.md](RUNBOOK.md)에 있다. 현재 `preflight.txt`의 결론은 **NOT READY**다.
이는 자동 승인 시스템의 거절이 아니라 실모델 미설정·공식 스키마 미검증에 따른 준비 상태다.

규정 확인에 사용한 공식 자료: [규정](https://nova.snubhai.org/rules/),
[평가 안내](https://nova.snubhai.org/evaluation/), [FAQ](https://nova.snubhai.org/faq/).
예선 고정 모델의 fine-tuning/LoRA를 수행하지 않았다. 허용된 개발 API와 제출 시 외부 API
제한을 구분하며, 아직 공모전 준수 인증·제출 승인을 받았다는 뜻은 아니다.
