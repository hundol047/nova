## 구현 순서와 완료 계약

1. **관계 매칭:** 식사 언급과 식후 증상 악화, 눕기와 눕자 호전/악화, 주관적인 fluttering과 실제 불규칙 맥박을 분리한다. 기존 assertion/주체/시간 범위와 source/span을 재사용한다. 별칭과 partial matching이 관계 조건을 우회하지 못하게 한다. 명시적 양성·부정·불확실·가족력·복수 절·한국어 대조군과 후보 support를 확인한다.
2. **증거 가중치와 명명:** 선택적 일반 증상 부재가 구체적 양성 패턴을 지우는 원인을 재현한다. 일반 증상끼리의 증거와 구체적 증거를 분리하며 임의 질환 보너스/위험도 가산점을 복구하지 않는다. 실제 양성의 직접 부정, 객관 반증, 중요 모순은 유지한다. 측정된 중증도만으로 특정 원인을 확정하지 않는다.
3. **정보 부족 계획:** 기존 unknown 종료와 긴급 평가를 유지한다. 맥박 이상+실신처럼 관찰된 위험 기전의 기존 최소 workup이 SOAP 계획에서 낮은 순위 때문에 사라지지 않게 한다. 계획은 수행 결과가 아니다. 예선에서 TEST를 실행하거나 정상 검사를 생성하지 않는다.
4. **제한된 표현·행동 연결:** 회전감/지속시간/체위 유발 관계의 실제 관찰을 기존 개념으로 연결한다. 가능한 EXAM만 연결하고 미지원 fixture 키를 시행된 검사로 간주하지 않는다. 지속 현훈·실신 전 어지럼·신경결손·거절 대조군을 보존한다.
5. **검색:** Top150/Weighted RRF/진단 Top25를 유지한다. 진단 순위를 위험 후보 교체로 훼손하지 않는 명시적 diagnostic/safety 분리를 구현한다. 기존 legacy 계약 테스트를 유지하고 새 production 경로를 별도 검증한다. 안전 watch는 점수/양성 근거가 아니며, 후속 실제 증거로 active 후보가 복귀할 수 있어야 한다.

새 임상 사실을 만들지 않는다. 필요하면 권위 있는 근거와 필드별 provenance를 먼저 확보한다. 전체 Tier-2를 얕게 늘리지 않는다.

## 검증과 보고

최소 대조쌍 → 실제 실패 사례 trace → 관련 테스트 → 전체 회귀 순서로 진행한다. 기존 예선230/P/Q 및 T 실패 사례, TEST 허용 M/G/I/J 등에서 새 오답과 위험 누락을 개별 비교한다. 모호한 라벨은 점수 손실과 임상 해석을 따로 기록한다. 안전 후보 분리의 초기/후속 retrieval 단계 손실도 측정한다.

최종 후보가 준비되면 미사용 합성 사례·정답·행동 계약을 실행 전에 동결/hash하고 동일 기준선/수정본에 실행한다. 결과를 보고 다시 수정하면 해당 세트는 개발로 승격하고 그 사실을 기록한다. 구현을 읽은 작성자의 합성 평가를 독립 임상 검증이라 부르지 않는다.

최종 전체 테스트의 pass/fail/skip/deselected를 구분하고 source mirror 바이트 일치, 격리 빌드/ZIP 감사/독립 mock, FINAL_REASONING_SHA와 ZIP hash를 연결한다. 실제 모델·공식 API는 미검증으로 둔다. 공개 소스·읽을 수 있는 보고서와 제한된 상세 traces/XML/ZIP 공개 범위를 구분한다.

완료 목표: 관계 허위 근거 재현 0, 기존 양성 대조군 유지, 새 위험 누락 0, 규칙 위반 0, 기존 scored 회귀가 있으면 원인과 판정을 명시한다. 달성하지 못한 목표를 PASS 또는 만점으로 표시하지 않는다.
