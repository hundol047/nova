# NOVA v50 — 20~25턴 정보수집과 단계별 진료

상태: **공식 점수 미측정 후보**. 만점이나 점수 상승을 보장하지 않는다.

## 변경 근거

사용자가 보고한 최신 점수는 정보수집 8.84/25, 진단추론 8.89/15, 검사·추적 4.67/10,
안전 13.75/15, 의사소통 5.61/15, 효율 16.44/20, 합계 58.20/100이다.
실제 리더보드 대화 로그는 제공되지 않았다. 코드상 결함과 합성 회귀 사례를 점검한 변경이며,
점수 변화의 원인이 입증되었다고 해석하면 안 된다.

## 동작

1. 안정 환자의 문진·신체진찰을 20~25회 행동에 배분한다. 첫 환자 걱정 질문과 진찰도 포함한다.
   주호소의 경과·양상·정도, 감별에 필요한 위험/동반 소견을 우선한다.
   관련 복약·알레르기·병력·기능 영향 및 진찰을 위한 행동 여유를 확보한다.
   긍정 응답의 약 이름, 알레르기 원인과 반응 등을 구체화한다.
2. 확보한 관찰로 주진단과 2~3개 감별을 검토한다. 실제 지지/반대 근거와 미확인을 구분한다.
3. 별도 계획 단계에서 검사 목적·근거·시점·결과별 조치, 현재 처치, 진료 수준,
   재진 시점·장소·재평가 항목, 주의사항, 생활 안내를 작성한다.
   누락되거나 말하기에 긴 항목이 있으면 한 번만 보완한다.
4. 진단 근거와 환자 걱정에 대한 답, 검사·처치·추적·주의사항·생활 안내를 먼저 하나씩 말한다.
   두 번째 설명 문장은 그 뒤에 배치한다. 환자의 이해 확인과 질문 기회도 남긴다.

정보수집 중에도 위험 여부는 매 행동마다 확인한다. 응급 소견, 마감, 서버 종료, 환자 거부,
유용한 질문 소진 등에서는 턴 목표를 채우려고 진료를 지연하지 않는다. 전체 49회 행동 상한과
제출 여유를 유지한다. 의학적으로 불필요한 질문을 늘려 최소 턴을 맞추도록 의도하지 않는다.

## 구체적 수정

- 문진 모델 호출 상한 12→5회, 한 묶음 최대 4→6개. 중요한 양성 답변에서는 묶음을 끊고 재검토한다.
- 최대 문진·진찰 35→25회. 기존 전체 35~49턴 목표보다 이번 사용자의 정보수집 요구를 우선했다.
- 질문과 답변이 이미 있는 행에 같은 내용을 합친 텍스트를 반복 전송하지 않는다.
- 두 번의 전체 진단·계획 작성 대신 진단 1회와 계획 1회를 사용한다. 정상 응답에서 최대 7회,
  계획 보완이 필요할 때 최대 8회가 기본 상한이다. 전송 재시도, 마지막 새 증상 재평가는 별도이다.
- 새로운 진단에 이전 규칙 프로필의 검사/치료/재진 간격을 섞지 않는다. 유효한 계획이 없으면 미확인으로 남긴다.
- 설명 여유를 14→18회로 조정하되 필요한 문장만 사용한다. 긴 문장을 잘라 조건/부정을 잃지 않는다.
- 세부 질문이 앞선 넓은 문진과 중복으로 오인되어 누락되던 경로를 수정했다.
- 기존 미확인/거절 처리, 근거 출처 검사, 진찰 거절 기록, 복약 안전 검사, 사례 간 독립성을 유지했다.

## 검증 범위와 제한

회귀 결과, ZIP 해시, 패키지 검증, 합성 HTTP 결과는 `artifacts/releases/nova-v50-publication.json`에 기록한다.
`nova-v50-controller-comparison.json`은 같은 합성 응답을 사용한 제어 흐름 비교다.
v49 컨트롤러와 프롬프트는 해당 커밋에서 읽지만 일부 임상 보조 코드는 현재 버전을 공유한다.
따라서 v49 전체 보관본의 독립적인 임상 재평가가 아니다. 문항 수와 요청 문자 수는 루브릭 점수나 실제 토큰 비용이 아니다.
합성 최종 계획은 모든 예시에 동일하게 사용되므로 임상 권고 또는 진단 정확도 검증으로 사용할 수 없다.

실제 Doctor 호출, 공식 샘플 채점, 리더보드 제출은 이 작업에서 수행하지 않는다.
blind v18은 재실행/튜닝하지 않는다. 비공개 정답이나 다른 사례의 메모리를 사용하지 않는다.
`run_dev_samples.py --candidate v50 --human-run`은 기존 사람 실행 경계와 정확한 후보 ZIP 검증을 유지한다.
