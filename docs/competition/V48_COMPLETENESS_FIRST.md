# v48: 필요한 정보와 실제 설명을 확보한 뒤 종료

사용자가 보고한 최신 점수는 정보수집 7.08/25, 진단추론 10.56/15,
검사·추적 4.97/10, 안전 12.50/15, 의사소통 4.94/15, 효율 20/20이다.
합계는 60.05/100이다. v46의 샘플 약 70점, 리더보드 약 49점이라는
별도 보고도 있다. 같은 사례·평가 조건인지는 확인하지 못했다.

이번 목표는 필요한 문진·진찰·설명을 늘리는 것이다. 효율 점수 유지를
위해 조기 종료하지 않는다. 전체 재작성 대신 v47의 관찰 근거·환자별
계획과 통신 보호를 유지하면서 종료 조건과 설명 처리를 고쳤다.

## 확인한 문제와 수정

- 빈 actions 또는 ready 응답 뒤 기본 문진 몇 개로 종료하던 경로를
  바꿨다. 누락된 경과·기능 영향·관련 병력 등을 실제로 묻고 새 답변을
  Doctor에게 다시 전달한다. 기존 증상군 문진은 보완 경로로만 사용한다.
- 계획 검토 한도를 5회에서 8회로 늘리고, 계획 응답 여유를 2,000에서
  4,000토큰으로 늘렸다. 추론 설정도 low에서 medium으로 변경했다.
  이는 사용자가 허용한 비용·턴 수 증가다. 실제 비용은 측정하지 않았다.
- 긍정적인 복약·병력·알레르기 답의 세부 확인을 한 번으로 끝내지 않는다.
  새 제어기에서는 최대 8개 영역의 보충 질문을 허용하며, 알레르기 반응
  확인이 일반 세부 질문 한도 때문에 막히지 않도록 했다.
- 모델이 여러 약 질문에 같은 넓은 topic 이름을 붙여도 이름·용량·빈도
  질문을 서로 중복으로 처리하지 않는다. 같은 질문과 같은 정보 반복은 막는다.
- 진찰이 없고 필요 없다는 설명도 없으면 한 번 더 검토한다. 실행되지
  않은 진찰을 정상으로 기록하지 않는다. 환자별 진찰 선택은 Doctor가 한다.
- 재평가 항목, 두 번째 주의사항·치료 문장, 교육 내용을 실제 설명에
  반영한다. 마무리용으로 14턴을 남기며 이해 확인, 질문 기회와 추가 답변에
  여유를 둔다. 전체 50턴·마감·즉시 이송 보호는 유지한다.
- 사람 전용 샘플 실행기가 새 제출 제어기와 같은 factory를 사용한다.
  v46~v48 후보 확인을 지원하고 ZIP과 staging의 manifest도 일치시킨다.
  구형 실행 경로 차이가 보고된 점수 격차의 원인이라는 증거는 없다.

## 검증 해석

`nova-v48-publication.json`과 같은 디렉터리의 보고서에 실제 실행 결과를
기록한다. 합성 환자와 고정 응답을 이용한 기능 검증이며, 실제 지정 모델의
진단 정확도·공식 점수 검증이 아니다. blind v18은 재실행하지 않았다.

고정 v47 제어기와 비교한 합성 사례에서는 18→27턴, Doctor 요청 3→5회,
묻지 않은 기본 문진 영역 7→0개였다. 답변이 모름이면 미확인으로 남겼다.
진찰은 두 버전 모두 1회였다. 설명은 9→11문장으로 늘었다. 이 비교는
같은 통신·임상 도우미를 공유하여 제어기 차이를 보는 제한된 비교다.

문진 영역을 질문했다는 사실만으로 필요한 정보를 모두 얻었다고 볼 수
없고, 턴 증가만으로 점수가 오르지도 않는다. v48의 실제 점수는 미측정이다.
특히 모델이 환자별 감별 질문·진찰을 잘 선택하는지는 공식 결과와 실제
진료 로그로 확인해야 한다. 만점이나 모든 영역의 상승을 보장하지 않는다.

## 사람 전용 샘플 실행

샘플 실행은 개발키를 가진 사람이 본인 컴퓨터에서 수행한다. 기존
`scripts/run_dev_samples.py`의 HUMAN-RUN 보호를 유지한다. v48 ZIP을
`submission/`에 정확히 풀고 저장소 소스와 맞춘 상태에서
`--candidate v48 --human-run`을 사용한다. 결과는 저장소 밖에 저장한다.
에이전트 개발 도구에서 개발키를 읽거나 공식 샘플을 실행하지 않았다.
