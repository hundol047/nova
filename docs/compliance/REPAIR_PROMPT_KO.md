# 규정 위험 및 개발 성능 보완 실행 프롬프트

현재 원격 `hundol047/nova`의 `offline/nova-competition-agent-optimization`을
확인한 뒤 아래 작업을 수행하라. 기준 원격 HEAD는 실행 시 다시 확인한다.

1. 공식 참가 규칙과 평가 페이지를 읽고 출처·라이선스, 모델, 증례 독립성,
   외부 API, 제출 파일 규정을 실제 코드와 비교한다.
2. 출처나 연구 출판 이용 권한이 미해결이면 공식 제출 가능으로 표시하지 않는다.
   현재 빌드는 로컬 PRE-GUIDE 전용으로 명시하고, 공식 제출 모드는 가이드·모델·
   스키마·출처 검증 전에는 실패하도록 한다. ZIP에 임의 파일이 섞이지 않게 한다.
3. 지식 자산의 버전·해시·출처·라이선스와 AI 생성 기록을 감사한다.
   누락된 다국어 매핑 기록을 포함한다. 역사적 모델·프롬프트·권한을 추정하여
   채우지 말고 UNRESOLVED 및 필요한 복구 증거를 남긴다.
4. 검색 후보 확장 등 일반 메커니즘의 개선 가설을 전체 Round M 개발 집합으로
   실험한다. 분모·정답·OOD 구분은 그대로 유지한다. 정확도뿐 아니라 critical
   recall, 검색·재정렬, TEST 수와 턴 수를 비교한다. 이득 없는 변경은 채택하지 않는다.
   OOD 조기 종료는 증거 부족과 실제 응급 상황을 혼동할 위험을 먼저 평가한다.
5. 60턴 상한, 4개 공식 액션, 증례 관련 실제 LLM 성공 게이트, provider lock,
   증례 독립성은 유지한다. 공식 가이드가 없으면 transport/schema를 추측하지 않는다.
6. 변경에 맞는 테스트와 전체 Doctor Agent 회귀를 실행한다. 최종 추론 코드가
   바뀌면 Round M 및 모든 개발 회귀를 재실행하고 제출본·검증 포인터를 갱신한다.
   바뀌지 않았다면 기존 런타임 검증은 보존하고 이번 추가 감사 결과를 구분한다.
7. 수정 완료·실험 기각·외부 증거 대기를 각각 실행 보고서에 기록한다.
   테스트 실패, 낮은 지표, 미해결 라이선스는 숨기지 않는다.
8. 이 브랜치에만 커밋하고 fast-forward로 원격 반영한다. main, force-push,
   불필요한 Actions 실행은 금지한다. HEAD와 원격 SHA 일치를 확인한다.

절대 금지: v19 실행·attempt/results/manifest 생성, v20 생성, 새 blind 실행,
증례 ID/정답 하드코딩, 생성 지식을 의학 출처로 간주, 실제 gpt-oss 검증 또는
공식 최종 제출 준비 완료를 허위로 선언하는 행위.

완료의 의미는 증거로 확인 가능한 수정의 적용과 잔여 차단 사유의 명시다.
공식 가이드, 주최측 모델 경로, 원저작/생성 기록이 필요한 부분은 해결된 것으로
표시하지 않는다. 프롬프트 실행 자체가 라이선스나 의학적 검토를 대신하지 않는다.
