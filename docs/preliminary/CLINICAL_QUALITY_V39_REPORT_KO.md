# v39 — 불완전한 병력 응답의 추가 확인

사용자가 보고한 점수는 정보수집 11.84/25, 진단추론 8.19/15, 검사·추적 4.67/10, 안전 13.75/15, 의사소통 6.44/15, 효율 19.63/20, 합계 64.52점이다. 채점된 대화 로그는 제공되지 않았다. 아래 변경은 코드에서 재현한 문제를 수정한 것이며 공식 점수 상승을 입증하지 않는다.

## 변경

- 약물·병력·알레르기·가족력·수술력·이전 진료·생활 영향 질문의 구체성 없는 긍정 답변에만 세부 확인을 추가한다. 항목당 한 번, 전체 세 번이며 모름·거절·음성 답변에는 반복하지 않는다. 응급 판단과 종료 예산이 우선이다.
- 직접 답한 병명·수술명 등은 질문의 단어를 반복하지 않아도 해당 문진의 응답으로 인식한다. 이는 문진 완료 여부이며 질환을 확정하거나 가족 병력을 환자 소견으로 바꾸는 기능이 아니다.
- 모델 근거가 비어 있는 경우 마지막 네 답변 대신 앞서 수집한 주요 문진을 질문·답변·턴 출처와 함께 보존한다. 미확인 정보는 별도로 기록하며 음성으로 간주하지 않는다.
- 프로필 기반 검사·추적 계획에 실제 관찰 항목과 미해결 문진을 연결한다. 복용약 이름을 모르면 약봉투·처방전 확인을 추적 항목으로 남긴다. 미시행 검사 결과는 비워 둔다.
- 갑상샘 검사 목적을 쉬운 말로 설명하고, 환자가 밝힌 검사·약물·회복·진료 일정 등의 걱정에 맞춰 짧게 응답한다. 같은 설명은 반복하지 않는다.

## 검증 범위

집중 회귀 185개 통과. Python 3.11 및 3.12 각각 전체 핵심 196개 모듈을 실행했으며 2,876개 통과, 1개 선택적 Torch 테스트 제외. 배포 기록 생성 후 별도 배포·권리 기록 검증을 합산한 최종 결과는 현재 검증 JSON과 `validation/*/complete.xml`을 따른다.

동일한 기존 합성 환자 3건에서 필수 문진 응답 커버리지 100%, 평균 28턴, 평균 Doctor 요청 2.33회를 유지했다. 이 시나리오들은 개발용 스크립트이며 실제 모델 평가가 아니다. 신규 단위 회귀 25개는 긍정 답변의 제한된 추가 확인, 거절·모름 처리, 병력의 주체 구분, 근거 보존 및 환자 걱정에 대한 응답을 확인한다.

230개 SDK 회귀와 v38 비교 결과는 `artifacts/clinical_quality_v39/comparison.json`에 저장한다. 이전 결과는 동일한 프로토콜·평가 스크립트 해시를 확인한 후 사용한다. Round M은 이 230건의 정확한 부분집합으로 추출하며 별도 실행으로 부풀리지 않는다.

ZIP은 고정한 실행 커밋에서 생성하고 독립 임시 폴더 실행, 가짜 HTTP 서버, 패키지 검사 및 정적 누출 검사를 수행한다. SDK는 변경하지 않는다. 원격 게시 커밋은 로컬 실행 커밋과 전체 파일 트리가 같음을 확인한다.

## 한계

실제 Doctor/API, 주최 측 샘플·공식 평가 및 새로운 비공개 블라인드 평가는 실행하지 않았다. 개발 키도 접근하지 않았다. 기존 임상 검토·출처 권리 미해결 항목을 승인 완료로 바꾸지 않는다. 진단 정답률·효율의 로컬 지표는 공식 영역별 점수가 아니며, 정확한 약점 분석에는 채점 대화 기록이 필요하다.

최종 합산: Python 3.11 및 3.12 각각 2,898개 통과 / 실패 0 / 선택적 Torch 테스트 1개 제외. SDK 230건의 주진단은 모두 이전과 동일하며, Top-1 203/222, 위험 사례 80/85, 평균 21.5087턴을 유지했다. 추가 질문이 필요한 응답은 새 회귀로 확인했고, 기존 고정 스크립트에서 공식 성능 향상을 주장하지 않는다.
