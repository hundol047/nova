# v38 정보 대비 턴 효율·진료 기록 개선

사용자가 2026-10-13 제공한 후속 점수는 정보수집 11.88/25, 진단추론 7.64/15, 검사·추적 3.44/10, 안전 11.25/15, 의사소통 5.61/15, 효율 17.36/20이다. 반올림된 영역 합계는 57.18점이다. 직전 영역 합계 51.97보다 5.21점 높지만 효율은 2.64점 낮아졌다. 제출 버전은 대화 흐름상 v37로 추정하며, 공식 실행 대화·세부 감점 사유·실제 모델 사용량은 제공되지 않았다. 점수만으로 감점 원인을 확정하지 않는다.

## 실제 변경

- 종료 대화에서 별도의 일반적 불확실성 문장을 반복하지 않고 작업 진단의 ‘의심’ 표현과 검사 후 치료 결정에 통합했다. 다음 진료 시점을 이미 설명한 경우 같은 문장을 다시 보내지 않는다. 이해했다고 기록하지 않고 환자의 실제 답을 보존한다.
- 이해 확인은 ‘1~2주’라는 문자열 전체 일치 대신 ‘한 주’, ‘2주’ 등 허용 범위 안의 표현을 인식한다. ‘네’나 ‘모르겠어요’만으로 이해를 판정하지 않는다. 추가 질문의 단순 인사에는 설명을 반복하지 않고, 검사·치료 질문과 현실적 부담에는 관련 응답을 한다.
- 수술력과 성인 흡연·음주를 누락 문진에 포함했다. 어린이에게 성인 질문을 일괄 적용하지 않는다. 이미 확인한 낮 기능 저하는 별도 일상생활 질문으로 되묻지 않는다. 미확인 항목을 음성으로 채우지 않는다.
- 추가 질문 계획은 low 추론·최대 2,048토큰으로 제한했다(기존 medium·4,096). 최종 진단 검토는 기존 설정을 유지했다. 추가 답이 있다는 이유만으로 재호출하지 않고 질문 계획이 명시적으로 재평가를 요구한 경우에만 다음 문진 계획 호출을 한다. 실제 토큰 비용 절감은 측정하지 않았다.
- S 기록은 질문·원답·가능한 경우 (+)/(-)/미확인 및 턴 번호를 보존한다. 이전 진료와 기능 영향은 현병력에 배치한다. 일반 과거력 부정을 특정 질환 음성으로 확대하지 않는다.
- A에는 검증된 엔진 후보의 지지·상충·미확인 항목을 구별한 짧은 해석을 추가한다. Doctor의 감별 지지·반대 사실도 실제 대화에 근거가 있는 경우만 유지한다. 진단 선택 및 사실 검증 기준을 느슨하게 하지 않았다.
- P에는 검사별 목적, 결과가 정상·불일치일 때의 재평가, 결과 확인 후 치료·의뢰, 재진에서 다시 볼 항목을 구체화했다. 기존 갑상샘·성장·진정제 관련 계획을 확장했으며 일괄 검사나 약물 용량을 추가하지 않았다. 일반 증례의 Doctor 프롬프트에도 같은 작성 원칙을 적용했다.
- 응급 우선, 30자 행동 제한, 서버 잔여 턴·시간 제한, 예선 TEST 미사용, 미시행 검사를 O.tests에 기재하지 않는 규칙을 유지했다.

## 재현·패키지

실행 소스는 `ded5b23d87927d328a8d32c710af35b0d9182ccc`. 로컬 실행 커밋 `2ba1a7b`와 전체 Git tree `060148f0b074d3c0c4486df784399b3d01a6fb56`가 같다. 이후 새 테스트의 환경 복구 fixture 누락을 수정했으며 제출 런타임은 변경하지 않았다. 영향을 받은 전체 테스트 묶음을 다시 실행해 병합한다. 최초 실패를 성공으로 계산하지 않으며 `validation/test-isolation-fix.json`에 원인과 범위를 남긴다.

제출 파일은 `artifacts/releases/nova-v38-submission.zip`. 실제 제출 코드와 동일한 소스·미러·ZIP 구성원 해시를 결합한 검증 기록은 `artifacts/verification/CURRENT_RELEASE.json`에서 찾을 수 있다. Python 3.11과 3.12에서 각각 **2,873개 통과, 1개 건너뜀(선택적 Torch 학습 검사)**. 실행 테스트 수와 ZIP 해시는 `artifacts/clinical_quality_v38/release-checks.json`을 따른다. 분리된 ZIP 실행, 로컬 가짜 HTTP SDK 연동, 비밀 값·금지 파일 검사를 수행한다.

```bash
python scripts/evaluate_official_fixture_efficiency.py --output fixture.json
python scripts/evaluate_clinical_quality.py --protocol evaluation/clinical_quality_v36_protocol.json --split all --mode complete --workers 3 --output sdk230.json
python scripts/run_regression_shards.py --output validation --workers 3
python scripts/validate_submission_zip.py artifacts/releases/nova-v38-submission.zip
```

Round M은 230건 중 128건(123건 채점)의 정확한 부분집합이며 별도 추가 실행이 아니다. 과거 TEST를 사용한 후보 단계 평가와 비교하지 않는다. 외부 DDXPlus·새 블라인드·실제 서버 채점·실제 모델 호출·컨테이너 자원 상한 검증은 이번에 실행하지 않았다. 참가자 키를 읽지 않았다. 기존 임상 검토·출처 권한 미확인 상태를 모의 테스트로 승인 상태로 바꾸지 않는다.
