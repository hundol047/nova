# N.O.V.A. Hospital-Grade CDS — Design

This design turns the N.O.V.A. Doctor Agent into a hospital-PoC-ready Clinical Decision Support
platform while keeping the competition submission a minimal, independent artifact. It is grounded
in the actual repository (branch `claude/practical-feynman-xv8uxs`), not a greenfield redesign — it
records the target architecture, the one authoritative hospital production path, and the concrete
component/data-flow decisions that satisfy `requirements.md`.

## 1. Guiding principles

1. **Decision support, not autonomy.** N.O.V.A. proposes; the clinician disposes. No auto
   diagnosis, no auto orders, no FHIR write-back. `clinician_review_required` is always `true`.
2. **One reasoning engine, adapter boundaries around it.** `nova_agent/` depends only on
   `PatientState` / `AgentAction`. Everything protocol- or transport-specific (competition schema,
   FHIR mapping, HTTP API, persistence) sits behind an adapter so it can change without touching
   the engine.
3. **Language-neutral core, translated edges.** Canonical `diagnosis_id` / action / concept ids are
   locale-independent. Only display strings are localized, on the way out.
4. **Fail closed and fail visible.** Auth, SMART scope, Postgres, and the LLM circuit breaker fail
   closed; degraded LLM state is always surfaced, never hidden behind the deterministic fallback.
5. **Honest verification.** Executable proof or `NOT VERIFIED`. No claim of clinical/regulatory/
   institutional/real-integration readiness without external evidence.

### 2.1 Production path decision (R15.1)

- **Authoritative hospital production path = `backend/`** (the integrated SynexAgent FastAPI app).
  It is the only path that reuses the hospital's FHIR/OIDC/SMART/RBAC/audit surface and Postgres
  persistence. All hospital-grade requirements target this path.
- **`production/` = reference / lightweight standalone deployment.** It is a self-contained FastAPI
  package around `nova_agent/` for demos, load-smoke, and a minimal container. It is **not** a
  second hospital production architecture and must be labelled as reference everywhere.
- **`submission/` = competition artifact.** Minimal (pydantic-only), independent, regenerated by
  `scripts/build_nova_submission.py`. Never carries FastAPI/Postgres/frontend/FHIR/OIDC.

These three are intentionally separate dependency surfaces and separate CI jobs so a failure in one
never gates another.

## 3. Backend component design

### 3.1 API surface (`/v1/nova/*`)

Existing (DONE): `POST /v1/nova/cases`, `POST .../{id}/observations` (idempotent by
`observation_id`), `POST .../{id}/decide`, `GET .../{id}`, `PATCH .../{id}/locale`,
`POST .../{id}/close`, `GET /v1/nova/metrics`, plus `/health`, `/health/subsystems`, `/ready`.

Design changes:
- **System status (R10.4):** extend `/health/subsystems` and `/ready` to report FHIR, Database
  (Postgres reachability), LLM (provider + circuit-breaker state), Auth, NOVA, Knowledge base — no
  secrets. Add the circuit-breaker `snapshot()` to this surface.
- **Error contract (R9/AQ):** a single JSON error envelope
  `{"error": {"code","message","request_id","retryable"}}` from a shared exception handler.
- **Request id (R9.4):** accept an inbound `X-Request-Id` (or generate one), thread it through
  service → audit → structured logs, and echo it in the error envelope and responses.

### 3.2 Persistence & migrations (R5, R6)

- `PostgresNovaCaseRepository` keeps optimistic concurrency (`version` column, `FOR UPDATE`) and the
  observation-idempotency primary key `(case_id, observation_id)`.
- **`state_schema_version` (R5.2):** add a column to `nova_cases`, default to the current
  `SCHEMA_VERSION` constant, written on save and read back; a round-trip test asserts it.
- **Migrations (R5.3):** introduce a lightweight, dependency-minimal, ordered SQL migration runner
  (`backend/app/services/nova_migrations.py`) with a `schema_migrations` version table, an ordered
  list of migration steps, and an idempotent `apply_migrations(conn)` — chosen over Alembic to
  avoid adding a heavy dependency to the backend runtime while still providing migration version +
  upgrade path + schema history. `_init_schema`'s `CREATE TABLE IF NOT EXISTS` becomes migration
  0001; new columns become subsequent migrations. Applied at startup and in the Postgres CI job.
- Save retry with jittered exponential backoff stays in the service layer; add a `nova_save_retry`
  counter (R9.1).

### 3.3 FHIR mapping (R3)

- Elevate lab/report/imaging mapping from free-text to a structured record that preserves:
  `canonical_id`, `raw_display`, `code_system`, `code`, `value`, `unit`, `status`, `observed_time`
  (effective), `issued_time`, `source`. Unmapped codes stay retained + counted.
- **Temporal/trend (R3.3):** a deterministic helper that, given ≥2 timestamped values for one
  analyte, classifies recency (recent/historical/stale by configurable windows) and trend
  (rising/falling/stable) — no clinical interpretation of a bare number with ambiguous units.
- **Report/imaging → reasoning (R3.2):** ensure `DiagnosticReport.conclusion` and
  `ImagingStudy.description` are surfaced into the presentation so candidate generation/scoring can
  consume them; prove with a mapper→reasoning test.

### 3.4 Observability (R9)

Add the missing named metrics: `nova_parse_failure`, `nova_case_conflict`, `nova_save_retry`,
`nova_critical_blocks` (alias/rename around the existing `nova_safety_blocks` so the canonical name
exists). Add `locale` to structured log fields. Emit explicit `nova_llm_degraded` and
`nova_storage_conflict` audit events.

### 3.5 Auth / SMART / RBAC (R4, R11.2)

Keep OIDC/JWKS verification and SMART fail-closed session handling. Add an explicit NOVA
endpoint-level check that the requested `patient_id` matches the SMART session patient when a SMART
session is present (fail closed). Real IdP / real SMART remain `NOT VERIFIED`.

## 4. Frontend design (R7, R8, R10.2)

### 4.1 Structure

```
frontend/src/
  i18n/
    index.js         # locale detection (saved → browser → ko), t() lookup, context/provider
    ko.js  en.js  ja.js  zh.js
  components/nova/
    NovaWorkspace.jsx        # orchestrates the case lifecycle + API calls
    NovaCaseHeader.jsx       # patient, case id, turn count, status, safety banner
    NovaCriticalPanel.jsx    # MUST-NOT-MISS (separated from differential)
    NovaDifferentialPanel.jsx# ranked differential, per-item evidence
    NovaNextActionPanel.jsx  # ASK/EXAM/TEST/DIAGNOSE + What/Why/Distinguishes
    NovaEvidencePanel.jsx    # supporting / contradictory / missing evidence
    NovaObservationForm.jsx  # enter ASK/EXAM/TEST result; stable observation_id
    NovaCaseTimeline.jsx     # per-turn ASK/EXAM/TEST/DIAGNOSE + result + timestamp
    NovaReviewPanel.jsx      # Accept / Modify / Reject + reason
    NovaSystemStatus.jsx     # FHIR / DB / LLM / Auth / NOVA + AI degraded states
```

`App.jsx` gains a NOVA tab that lazy-loads `NovaWorkspace`; the existing SynexAgent tabs are
untouched. No component holds the whole app; each panel is a focused file.

### 4.2 Data flow

`NovaWorkspace` owns case state and calls the real `/v1/nova/*` API via `lib/api.js`. The decide
response fields map directly to panels: `red_flags` → CriticalPanel; `differential[]` →
DifferentialPanel (+ EvidencePanel per selected item); `recommended_next_action` → NextActionPanel;
`llm_degraded` + `/health/subsystems` → SystemStatus. Confidence is shown as LOW/MEDIUM/HIGH only —
never a raw `%` unless the backend marks it calibrated.

### 4.3 i18n

A tiny dependency-free i18n (nested key dictionaries + `t(key, vars)`), no new npm package.
Selection priority: `localStorage` → `navigator.language` → `ko`. Canonical ids never localized;
`t()` only touches display strings. Mid-case switch calls `PATCH .../locale` and re-decides without
resetting local case state.

### 4.4 Idempotent observations (R8.6)

`NovaObservationForm` generates one `observation_id` (uuid) per logical observation and reuses it on
retry; the backend PK gate makes replays no-ops, so a network retry never advances the turn twice.

### 4.5 Accessibility & states (R8.9, R8.10)

Every panel implements loading / empty / error / degraded / retry. Critical state uses icon + text
+ shape, not color alone. Dialogs trap focus and support Escape; interactive elements have
accessible names. Layout verified at 1920 / 1440 / tablet-landscape.

## 5. Reasoning stabilization design (R1, R2)

No blind-case-specific rules. Improvements are disease/phrase-scoped or generic-structural:
- **Presentation rebuild (R1.3):** confirm each turn rebuilds from full `PatientState`; add a
  negation-non-reinjection regression.
- **Objective evidence (R1.4):** extend deterministic normalization across the analyte list; guard
  against interpreting bare numbers with ambiguous units.
- **Anchoring (Z):** a generic rule — a previous/benign diagnosis is not the current-episode
  diagnosis when new evidence (new focal deficit, different pattern, persistence, new risk factor,
  hemodynamic instability) is present — implemented structurally, never keyed to a blind case.
- **Stop policy / turn efficiency (AA, AB):** keep minimum-discriminative-evidence gating and the
  information-gain/critical-discrimination/redundancy-penalty selection; verify with tests.
- **Semantic dedup (AC):** canonical-concept dedup across all four languages.

## 6. Competition design (R12)

`competition/schema.py` + `adapter.py` stay a disclosed placeholder. If and only if the user
supplies the official N.O.V.A. 2026 API document, those two files (and the two translation
functions) are updated to match; nothing else changes. Until then: `Official competition API:
NOT VERIFIED`. `scripts/build_nova_submission.py` regenerates `submission/` after any `nova_agent/`
change; a sync test fails CI on drift.

## 7. CI/CD design (R14)

Target jobs on PRs to the integration branch (`claude/practical-feynman-xv8uxs`) and to `main`:
- `nova-agent` (mock provider; pytest + evaluation smoke + submission sync) — exists.
- `production` (standalone package tests + load smoke + docker) — exists.
- `production-backend` (backend integration tests + load smoke + docker) — exists.
- **`postgres-integration` (NEW):** `services: postgres:16`, sets `NOVA_TEST_POSTGRES_URL` +
  `NOVA_CI_REQUIRE_POSTGRES=1`; runs the Postgres repo/concurrency/audit + migration tests. The
  tests turn a *CI* skip into a failure when `NOVA_CI_REQUIRE_POSTGRES=1` (local skip still
  allowed). Verifies restart recovery, concurrent writers, audit persistence, locale persistence,
  case close.
- **`frontend` (NEW):** `npm ci` + `npm run build` + vitest; a browser smoke (Playwright where
  feasible) for page load, patient open, NOVA tab, case create, decision visible, observation
  submit, locale switch, review.
- `competition-readiness` — exists; SKIPPED when no real secret; NOT VERIFIED otherwise.
- **Security (NEW step/job):** repo-wide secret scan + pip/npm dependency vulnerability report.

Triggers broadened so these run on the feature/integration branches, not only `main`.

## 8. Environment & verification note

The implementation environment for this spec is **network-isolated** (no pip/npm/docker/Postgres/
external LLM/FHIR). Therefore local execution of the Python/JS suites, container builds, and blind
benchmarks is **not possible here**; correctness is established by (a) static reasoning and (b) the
repository's own GitHub Actions after push. Every item that cannot be executed locally is reported
`NOT VERIFIED (requires runnable env)` and is delegated to CI. Blind v7's single first run likewise
requires a runnable Python env and is `NOT VERIFIED` until run there.
